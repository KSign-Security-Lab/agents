Kubernetes serves the models.
Your laptop runs everything else.

Anything that needs a GPU is a pod in a k3s cluster on the GPU machines. Anything that doesn't is Postgres and Redis in Docker on your own machine, plus api and web as host processes with hot reload. Nothing local needs CUDA, so a Mac is fine.

Two kinds of machine

A GPU machine holds no configuration of its own — it joins the cluster and is done. A developer's machine is a two-line .env. That asymmetry is the point: adding GPU capacity is an operation on the cluster, not an edit on every laptop.

Why a laptop only needs one address

GPU_HOST is any node's IP. The models sit behind Kubernetes Servicees on fixed NodePorts — 30862 for vllm, 30863 for infer — and each routes to whichever pod is ready. A developer never learns how many GPU machines exist, which one answered, or that one was replaced this morning.

This is what let the nginx gateway, GPU_PEERS, and per-machine VLLM_GPUS bookkeeping be deleted outright: about 150 lines of compose, nginx config and shell that a Service does for free.

Adding GPU capacity

You wantDo thisWhat happens
more pods on machines you have kubectl -n agents scale deploy/vllm --replicas=3 The scheduler places them on nodes with a free card. One with no card left stays Pending rather than failing oddly.
a whole new machine sudo k8s/setup.sh agent <ip> <token>, then scale It registers itself, the device plugin lands on it automatically and advertises its cards, and the Service adds the new pod once it passes readiness. No config changes anywhere — no .env edit on any laptop, nothing restarted.
a model too big for one card nvidia.com/gpu: 2 One pod holds two cards and vLLM splits the model across them, working that out itself — which is why an odd card count needs no second service definition.

How GPUs are divided

Whole cards, never fractions. Kubernetes will not give two pods the same GPU, and for extended resources it forces requests to equal limits — so overcommitting isn't something you can do by accident.

Sharing one card between pods needs time-slicing, MPS or MIG. None suit vLLM, which preallocates its share of the card at startup and would collide with a co-tenant.

ServiceRuns asWhat it does
postgres container · :5433 pgvector. Documents, chunks, the branching message tree, and both vector columns — vector for dense, sparsevec for lexical. Also chunk_spans, the text-offset → page-rectangle map that makes citations clickable.
redis container · :6380 The ingest queue. api enqueues an upload; the worker consumes it.
api host · :8000 · reloads FastAPI + LangGraph: the agent, SSE streaming, citation resolution. Carries no torch at all — every GPU call goes out over HTTP — which is why it runs on your host.
web host · :3000 · reloads Next.js UI, and the proxy in front of it: the browser never sees the API, it holds an httpOnly cookie and this tier attaches the token server-side.
worker container · opt-in convert → extract → chunk → embed → categorize. LibreOffice, H2Orestart for HWP, PyMuPDF, OCR and ffmpeg are why the image is large, so it starts only with COMPOSE_PROFILES=dev,ingest.

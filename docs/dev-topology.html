문서 기반 에이전트 · make gpu / make dev

One GPU server serves the models.
Your laptop runs everything else.

Nothing you run locally needs a GPU, so this works on a Mac. The two services that need CUDA live on the shared box; the two services you actually edit run on your host with hot reload.

What to run, on which machine

GPU server

Once, by whoever owns the box — then again only after a reboot.

First time

make setup            # writes docker/.env
$EDITOR docker/.env    # VLLM_A_GPUS, BIND_ADDR

Serve it

make gpu          # or: make gpu MODE=tp2
make gpu-logs S=vllm-a

No Postgres, no Redis, no web, no worker on this box — compose.gpu.yml contains only these two services.

Your machine

Every developer, on their own laptop.

First time

make dev-setup
$EDITOR docker/.env.dev   # set GPU_HOST

Every day

# only if the GPU box stays on loopback
ssh -N -L 8602:localhost:8602 \
       -L 8603:localhost:8603 gpu-host

make dev

Starts the containers, migrates, seeds dev@agents.dev / devdev, then runs api and web with reload. Ctrl-C stops the two processes and leaves the containers up, so the next run takes seconds.

Running less than everything

CommandStartsReach for it when
make dev containers + api + web the normal case
make dev S=deps containers only, migrated and seeded you want to launch api from your IDE — point it at .venv/bin/python, working dir apps/
make dev S=api just api two terminals, or web is already running
make dev S=web just web frontend-only work
INGEST=1 make dev the above, plus the worker container you're touching ingest — it's a big image, so it stays opt-in
make dev-down / dev-reset stops containers / stops and wipes the local DB done for the day / the schema drifted

There is no third mode

These two commands are the whole system. make gpu needs CUDA; make dev needs nothing but Docker. They're independent, so if you want everything on one machine you run both — there is no separate all-in-one path to learn, and no combined stack that can drift from what developers actually run.

Config is two files and nothing else: docker/.env on the GPU server, docker/.env.dev on your laptop. Both start as .example copies written by make setup and make dev-setup.
